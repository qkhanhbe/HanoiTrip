## Phạm vi đã kiểm chứng

- Terraform `1.16.4`; `fmt`, init và validate đạt cho `bootstrap/` và `app/`.
- Backend Azure Blob tách khỏi app stack, dùng Microsoft Entra ID; Storage
  Shared Key bị tắt.
- App stack gồm resource group, ACR, App Service production + staging slot,
  MySQL Flexible Server, Key Vault, user-assigned managed identity, VNet/subnet,
  Log Analytics, diagnostic settings, autoscale, action group và metric alerts.
- Image nguồn đã review được build/push bằng wrapper; App Service pull qua
  `AcrPull`, không dùng ACR admin credential.
- Key Vault default-deny; App Service đọc secret qua delegated subnet và
  `Key Vault Secrets User`.
- MySQL chỉ cho phép bốn outbound IP thực tế của App Service, bắt buộc TLS 1.2.

## Backend và locking

Backend được tạo một lần trong `rg-hanoitrip-tfstate`, container `tfstate`, blob
`hanoitrip.tfstate`. Sau apply backend:

- Queue logging có `Read/Write/Delete=true`.
- Plan tiếp theo trả `No changes`.
- Một Entra-authenticated lease tạm được đặt lên đúng state blob.
- `terraform plan -lock-timeout=0s` bị chặn với exit code `1` do state lock.
- Lease được giải phóng bằng `trap`; blob trở về `available/unlocked`.

## Destroy → apply sạch

Saved destroy plan đầu tiên được kiểm tra bằng JSON trước khi chạy:

```text
actions: delete=38
resource_groups: [rg-hanoitrip-dev-js4qsu]
unexpected_actions: []
Apply complete! Resources: 0 added, 0 changed, 38 destroyed.
```

Sau destroy: app state có `0` resource, resource group ứng dụng không còn;
backend resource group và state container vẫn tồn tại, state blob `unlocked`.

Từ state rỗng, `scripts/terraform/apply-app.sh -input=false -auto-approve`
chạy liền mạch, không có thao tác Portal:

```text
Plan: 34 to add, 0 to change, 0 to destroy.
Apply complete! Resources: 34 added, 0 changed, 0 destroyed.
Plan: 4 to add, 0 to change, 0 to destroy.
Apply complete! Resources: 4 added, 0 changed, 0 destroyed.
Resolved Key Vault references for production.
Resolved Key Vault references for staging.
Verified production: MySQL health is ready and build SHA is 799e9c3d7787eb71.
Verified staging: MySQL health is ready and build SHA is 799e9c3d7787eb71.
```

Lượt apply thứ hai là bước reconcile có chủ đích: lấy bốn outbound IP vừa được
Azure cấp rồi thêm đúng bốn MySQL firewall rules. Không có rule `0.0.0.0` hay
client IP cũ.

## Các lỗi đã phát hiện và khép lại trong quá trình

- Chuẩn hóa IPv4 `/32` trước khi gửi Storage network rules.
- Chuyển mặc định sang `eastasia` để phù hợp Azure Policy của subscription.
- Chuyển Blob/Queue data plane sang Entra ID vì Shared Key bị tắt.
- Tách MySQL firewall thành apply hai pha vì outbound IP chỉ biết sau apply.
- Bổ sung health-check eviction cho production và staging.
- Lọc phần tử outbound IP rỗng trước khi tạo firewall rule.
- Thay image placeholder bằng image ứng dụng build từ source đã review.
- Route Key Vault reference qua VNet/subnet thay vì dựa vào public outbound IP.
